The eleven-second add

Type three things. The system
remembers everything else.

Menu work is mostly re-entry: the same dish, the same photograph, the same price, next season. Lumière refuses to ask twice. It normalises every name, fingerprints every upload and keeps an append-only ledger, so a dish you photographed once is photographed forever.

sha-1 photo fingerprint dedupe fuzzy twin matching price ledger fallback

Name · price · stock

That is the entire form. The studio infers the chapter, station, prep time and par level from your own history.

The photo is already there

If any twin of that dish has ever had a picture, it is attached automatically and labelled “auto-inherited”.

Duplicates become restocks

Re-adding an existing dish never clones a row — it tops the stock back to par and logs the movement.

One file, many dishes

Re-uploading an identical picture is deduplicated by checksum and re-linked, so the media folder stays clean.

Every number is auditable

Sales drain stock through menu_stockmovement; price edits land in menu_pricechange.

Data model

Eleven tables, deliberately drawn.

Constraints at the database level, indexes on every hot path, ledger tables instead of soft updates. Row counts are live.
